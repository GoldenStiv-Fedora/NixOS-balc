# balc

Локальное приложение для мониторинга и управления парком NixOS.
Запускается под пользователем `balc` на любом ПК парка.

## Что показывает

- список ПК по MAC-адресу;
- онлайн/офлайн;
- последний успешный коммит и коммит в GitHub;
- результат последней сборки и текст ошибки;
- текущее поколение, версию NixOS, uptime, место на диске.

## Действия

- **Обновить** — опросить известные ПК по SSH.
- **Найти ПК** — просканировать подсети и добавить найденные ПК.
- **Пересобрать** — по правой кнопке на ПК: скачать GitHub и запустить
  `nixos-fleet-rebuild.service` на выбранном ПК.
- **Переименовать** — задать понятное имя. Имя привязывается к MAC-адресу.
- **Открыть SSH** — открыть терминал `ssh balc@IP`.
- **Подсети…** — список CIDR для поиска ПК.
- **Мастер-пароль…** — расшифровать `token.enc` на время работы приложения.
- **Забыть токен** — стереть расшифрованный токен из памяти.
- **Токен GitHub (простой)…** — сохранить или удалить открытый токен в файле.

## Инвентарь и GitHub

Инвентарь хранится в `inventory.json` в корне репозитория. Приложение читает
его с GitHub и объединяет с локальной копией:

`~/.config/balc/inventory.json`

Перед отправкой приложение перечитывает `inventory.json` из GitHub, сливает
записи и только потом делает коммит. Поэтому ПК не затирают имена друг
друга:

- имя побеждает по самому свежему `updated_at`;
- IP — по самому свежему `last_seen`;
- списки `scan_subnets` объединяются;
- при конфликте (`409`/`422`) приложение повторяет попытку с новыми данными.

## Токен GitHub

Токен нужен для записи имён и подсетей в GitHub. Он хранится в репозитории
зашифрованным мастер-паролем — в файле `token.enc` рядом с приложением
(`apps/balc/token.enc`). Приложение получает его через меню
«Парк → Мастер-пароль…» и держит только в памяти, до выхода или «Забыть
токен».

Создание файла (токен и пароль вводятся скрыто):

```
python3 apps/balc/token_tool.py apps/balc/token.enc
```

На установленном приложении доступна команда `balc-token-setup ПУТЬ/token.enc`.
Готовый `token.enc` коммитится в GitHub; служба синхронизации копирует его на
все ПК, и смена токена не вызывает пересборку системы.

Безопасность: репозиторий публичный, поэтому защита держится только на
мастер-пароле — он должен быть длинным (5–6 случайных слов или длинная
фраза). Не теряйте его: без него токен не восстановить.

Устаревший способ — открытый файл `~/.config/balc/github_token` (права
`0600`). Он работает как запасной вариант, но его лучше удалить после
перехода на `token.enc`. Переменная `BALC_GITHUB_TOKEN` имеет приоритет над
всем.

Без токена имена сохраняются локально, а остальные ПК увидят их только после
появления токена или ручной правки `inventory.json` в GitHub.

## SSH

Приложение подключается как `balc` с паролем из конфига. На всех ПК должен
быть включён SSH и задан пароль пользователя `balc`. Пересборка запускается
через `sudo -n /run/current-system/sw/bin/nixos-fleet-rebuild`; для этого в
`git-sync.nix` добавлено правило sudoers без пароля.

## Конфигурация

Приложение ставится модулем `balc.nix`, который лежит в этой же папке
(`apps/balc/balc.nix` в репозитории). Модуль добавляет пакет только в профиль
пользователя `balc` (`users.users.balc.packages`), поэтому `user` приложение
не видит.

При обновлении из GitHub служба синхронизации копирует папку `apps/balc/`
целиком в `/etc/nixos/apps/balc/` (включая `balc.nix`), а `inventory.json` —
в `/etc/nixos/apps/inventory.json`, после чего система пересобирается.
